===============================================
Planner Project - API Docs (Frontend uchun)
===============================================

1. UMUMIY TUSHUNCHA
-------------------
Bu API project, task, user, role, permission, task status va task priority larni
boshqarish uchun ishlatiladi.

Authentication Laravel Sanctum token orqali ishlaydi.

Base URL:
  http://127.0.0.1:8000/api

Protected endpointlarda header yuboriladi:

  Authorization: Bearer {token}
  Accept: application/json
  Content-Type: application/json

Standart response shakli:

{
    "success": true,
    "message": "...",
    "data": ...
}

3. USERS API LAR
=================

3.1. Userlar ro'yxati — GET /api/users
--------------------------------------
Auth: Bearer token kerak
Permission: user.view

Query params:
  - search: string, nullable
  - role_id: integer, nullable
  - per_page: integer, default 10

Request misol:
GET /api/users?search=ali&role_id=2&per_page=10

Response misol:
{
    "success": true,
    "message": "Users list",
    "data": {
        "data": [
            {
                "id": 1,
                "name": "Ali",
                "phone": "998901234567",
                "role": {
                    "id": 2,
                    "name": "developer"
                }
            }
        ]
    }
}


3.2. User yaratish — POST /api/users
------------------------------------
Auth: Bearer token kerak
Permission: user.create

Fieldlar:
  - name: required, string
  - phone: required, unique
  - password: required, min 6, confirmed
  - role_id: required, exists roles.id

Request body:
{
    "name": "Ali",
    "phone": "998901234567",
    "password": "password",
    "password_confirmation": "password",
    "role_id": 2
}

3.3. User ko'rish — GET /api/users/{user}
-----------------------------------------
Auth: Bearer token kerak
Permission: user.view

Request misol:
GET /api/users/1


3.4. User yangilash — PUT /api/users/{user}
-------------------------------------------
Auth: Bearer token kerak
Permission: user.update

fieldlar:
    'name' => 'sometimes|string|max:255'
    'phone' => 'sometimes','string','unique' (actual turgan phone ignor qilgan holda unique)
    'password' => 'nullable|string|min:6|confirmed'
    'role_id' => 'sometimes|exists:roles,id'

Request body:
{
    "name": "Ali Updated",
    "phone": "998901234567",
    "password": null,
    "role_id": 2
}

3.5. User o'chirish — DELETE /api/users/{user}
----------------------------------------------
Auth: Bearer token kerak
Permission: user.delete

500 — server error


12. FRONTEND UCHUN TAVSIYALAR
==============================

- Login qilingandan keyin token localStorage yoki cookie ichida saqlanadi.
- Har bir protected requestda Authorization: Bearer {token} yuboriladi.
- 401 bo'lsa user login sahifaga qaytariladi.
- 403 bo'lsa "Sizda ruxsat yo'q" degan xabar ko'rsatiladi.
- List sahifalarda filterlar query params orqali yuboriladi.
- Task listda filterlar birga ishlaganda AND bo'ladi.
  Masalan:
    /api/projects/1/tasks?assigned_to=2&status_id=1
  bu assigned_to=2 VA status_id=1 bo'lgan tasklarni chiqaradi.

- Task create/update formda:
  1) avval project tanlanadi
  2) shu projectga biriktirilgan developerlar ko'rsatiladi
  3) status va priority tanlanadi
  4) deadline kiritiladi

- Role create/update formda permissionlar multi-select bo'lishi kerak.
- Project detail sahifada developers ro'yxati ko'rsatiladi.
- User detail sahifada role ko'rsatiladi.
